Building OPTECH DataHarbor

Ben Haddley · August 20, 2026 · 6 min read

A local-first research gateway that puts my own documents, an offline Wikipedia mirror, live web search, and a local AI summarizer behind one search bar — no cloud, no tracking, no dependency on connectivity.

Most of my research day looks the same regardless of the topic: I’m bouncing between a handful of PDFs and Word docs I already have, a reference site I half-remember, and a general web search to fill in the gaps. Three different tools, three different search boxes, and none of them know about each other. OPTECH DataHarbor is what happens when I got tired of that and built one search bar that actually covers all three — plus an offline encyclopedia mirror and a small local AI that reads the results back to me, all running on a machine with no internet connection required if it comes to that.

The shape of the problem

The actual requirement was narrower than “build a search engine”: I wanted local documents, an offline reference library, and the live web searchable from one place, without sending any of it to a cloud service. A lot of my reading is geopolitical and defence-adjacent — the kind of research where “it’s fine, it’s just a search query” isn’t a satisfying answer, and where I’d genuinely rather the tool still work with no signal at all.

That ruled out most of the obvious shortcuts. A hosted search API means every query leaves the machine. A cloud LLM for summarization means the same for every result snippet. Wikipedia’s live site assumes connectivity I can’t always guarantee. So the constraint became the design: everything runs in Docker, on localhost, and the one exception — live web search — goes through a privacy-respecting meta-search engine instead of a tracked one.

What’s actually running

DataHarbor is a Docker Compose stack of about eight small services rather than one monolith, mostly because each piece is genuinely a different problem:

  • Meilisearch indexes local documents and news with hybrid search — full-text plus vector similarity via a small HuggingFace embedding model (BAAI/bge-small-en-v1.5), so a query matches on meaning as well as exact words.
  • Kiwix serves a stack of offline ZIM files — Wikipedia slices (geography, history, medicine, sociology), several Stack Exchange communities (security, crypto, CS, GIS, ham radio, politics), an OPSEC field manual, and a military medicine reference. All of it works with the network cable pulled out.
  • SearXNG handles live web search without becoming a tracking vector itself — it’s a meta-search engine that queries other engines on your behalf and doesn’t log or profile you.
  • A small ingest daemon watches a folder with watchdog: drop a PDF, DOCX, TXT, Markdown, or HTML file in, and it gets text-extracted, hashed for a stable ID (so re-dropping the same file updates it instead of duplicating), indexed into Meilisearch, and filed into done/ or failed/ depending on whether it worked.
  • A news poller pulls from a curated set of geopolitical and defence RSS feeds — BBC’s regional world feeds, USNI News, Defense One, Reuters, Al Jazeera — on an hourly cycle.
  • A countries service — FastAPI over SQLite — builds a nation capability database from RestCountries and World Bank data: population, GDP, military spending as a share of GDP, personnel counts across up to twenty years, and alliance membership (NATO, Five Eyes, AUKUS, QUAD, ANZUS, SCO, CSTO, ASEAN, and others).
  • Redis backs SearXNG’s session store, and a plain nginx container serves the single-page frontend and proxies API calls to everything else.

None of it talks to the internet except the news poller and the live web search — and both of those are the only two things that inherently need to.

The parts I actually enjoyed building

The search bar itself is the least interesting part of this project. A few pieces of it were more fun to get right.

Signal over noise on the news feed. A raw RSS pull of “world news” is mostly not what I want — it’s celebrity deaths and sports scores next to the occasional thing that actually matters. Rather than index everything, the poller gates general-purpose feeds through a keyword allowlist — military organisations, hardware, conflict and security events, named geopolitical actors — and only skips that gate for sources that are already narrowly defence-focused (USNI, Defense One). It’s not clever NLP, just a deliberately curated word list, but it keeps the index actually useful instead of a firehose.

Country detection that understands how people actually refer to countries. Nobody searches for “China” by typing “CHN”. They type “the PLA”, “Beijing”, “the Kremlin”, or “NZDF”. The countries service ships a hand-built alias table mapping military organisation names, capital cities, and common shorthand to ISO country codes, so a query mentioning any of those pops up an inline capability card — population, GDP, a fifteen-year military spending sparkline — without the user having to know or type the “correct” country name.

Being honest about data confidence. Not every field is equally solid. Alliance membership is a matter of public record; military personnel figures reported to the World Bank are closer to an estimate. Rather than present everything with the same false certainty, every country card carries an explicit confidence label per field — confirmed, likely, estimated, or unknown — so a sparkline doesn’t get mistaken for ground truth it isn’t.

A local AI that never leaves the machine. After a search settles, a small model (llama3.2:1b, running on the same host through Ollama) reads the top results and streams back a short plain-language summary directly in the browser. It’s genuinely useful for skimming a pile of hits quickly — and because it’s a local model talking to a local search index, the query and every result snippet it sees stay exactly where they started.

What it feels like day to day

In practice, the workflow is: type once, get local docs, offline wiki hits, and live web results side by side, filterable by source; if a country comes up, its capability card is just there; if I want, the on-device model gives me the two-sentence version before I start reading anything in full. Dropping a new report into the inbox folder means it’s searchable within seconds, filed automatically, with no manual re-indexing step to remember.

It’s not trying to be a product — there’s no user account, no telemetry, no reason for it to phone home. It’s the tool I wanted and didn’t find, built to run entirely on hardware I own, that keeps working exactly as well with the wifi off as it does with it on.
