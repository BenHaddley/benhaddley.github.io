Baggies' Guide to HCLOS

Author · 2026 · 4 min read

A hands-on field and training guide for Cambium HCLOS microwave radio links — covering kit, wiring, mast assembly, switch configuration, and a symptom-first troubleshooting section, condensing scattered vendor documentation and word-of-mouth operator knowledge into a single reference.

Overview

Cambium HCLOS (High Capacity Line-of-Sight) radios shoot a microwave beam between two dishes to create a high-bandwidth wireless bridge — effectively an invisible Ethernet cable extending a LAN over distance. I wrote a 12-section field guide covering every node configuration the kit supports (point-to-point, multipoint, retransmission, and switched retransmission), how to physically assemble and wire each one, how to operate the Cambium Web UI end to end, and how to diagnose the failures that actually show up in training and in the field.

Problem

The kit itself comes with vendor documentation written for a general commercial installer, not for someone learning it hands-on in a training environment and then deploying it in the field. That left a gap between reading a manual and actually being able to stand up a link: knowing which of several near-identical cables goes where depends on which of four node types you're building, and troubleshooting knowledge — what a particular LED or a red pointing graph actually means — normally only lives in whoever set the kit up last time, not in any document.

Constraints

  • Had to cover four distinct node roles (point-to-point/dish, multipoint/panel, retransmission, and switched point-to-point retransmission) that reuse the same physical components — ODU, PSU, dish or panel — wired differently depending on the role
  • Had to work for two different contexts with different requirements: a classroom/training setup where transmit power needs to stay low to avoid interference, and a live field deployment where it needs to be at full strength
  • Needed exact, vendor-specific steps (precise Cambium Web UI menu paths, literal Cisco IOS commands) rather than generic networking advice, since a reader follows it live against real hardware
  • Troubleshooting content had to be usable mid-problem — a reader reaching for that section is already stuck, not browsing for background reading

Approach

The guide is organized around what the reader is physically doing rather than the vendor's own menu structure: a kit list and wiring diagram per node type (matching ODU 'V'/'H' ports to the correct dish or antenna connector every time), a walkthrough of the Cambium cnMatrix Web UI from first login through arming the installation and pointing the antennas, a dedicated section on the Cisco switch configuration and tunneling settings a switched-retransmission node needs, physical mast assembly steps, and a troubleshooting section structured as symptom-first checklists rather than prose.

Key Decisions

Split the physical setup guide by node type instead of one generic wiring section

Reasoning:

The same ODU, PSU, dish, and panel components get wired differently depending on whether you're building a point-to-point, multipoint, retransmission, or switched-retransmission node. Conflating them into one generic wiring section would leave the reader guessing which instructions actually applied to the specific kit in front of them.

Alternatives considered:
  • One combined wiring guide covering all node types together

Document both a training transmit-power setting and a field setting explicitly, instead of one 'correct' number

Reasoning:

The same guide gets used indoors during training and outdoors on exercise. Writing down -15 dBm for classroom setups and 27 dBm for live deployment, as two named settings rather than one general instruction, stops the field-strength habit from being carried unthinkingly into an indoor training environment where it just creates interference.

Alternatives considered:
  • List only the field-deployment power setting and assume the reader adjusts it down for training

Structure troubleshooting as symptom-based checklists instead of a general FAQ

Reasoning:

Someone debugging a dead link in the field needs to go from what they're actually seeing — no Web UI access, a red pointing graph — straight to a short ordered list of checks, not search through prose to find the relevant advice. Framing each section around an observable symptom (with a general pre-flight checklist first) matches how the guide is actually used under pressure.

Alternatives considered:
  • A single general FAQ or notes section covering common issues

Tech Stack

  • Cambium Networks HCLOS radios (ODU, PSU, panel & parabolic dish antennas)
  • Cambium cnMatrix Web GUI
  • Cisco IOS (switch configuration & tunneling)
  • Technical/instructional documentation

Result & Impact

A single 12-section reference — kit and wiring per node type, mast assembly, Cisco switch/tunneling configuration, full Cambium Web UI walkthrough, and a symptom-first troubleshooting section — replacing what would otherwise be scattered vendor manuals and whatever the last person to set up a link happened to remember.

Learnings

  • Good field documentation matches the reader's actual workflow — which node am I building right now — rather than the vendor's own organizational structure of settings grouped by menu
  • Troubleshooting content is most useful written symptom-first, since a reader opening that section is already mid-problem, not browsing for background reading
  • Writing down the difference between a training-safe and a field-ready configuration explicitly (transmit power) stops a habit formed in one context from becoming a bad default carried into the other
