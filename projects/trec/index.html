TREC — Trentham Operations Monitor

Creator — Public-data integration and frontend engineering·2026·5 min read

A New Zealand-first situational-awareness dashboard combining a geographic map, animated weather radar, earthquakes, road information, public defence reference locations, news, radio, webcams and selected international OSINT datasets.

Overview

TREC is an unofficial, browser-based public information monitor focused on Trentham Military Camp and the Wellington region, with switchable New Zealand, Pacific and global views. Built on the open-source World Monitor project, it brings together public information that normally lives in separate news sites, weather services, hazard feeds and geospatial portals. The interface places the map at the centre and keeps the original sources, timestamps and data limitations visible. TREC is not an NZDF product, is not affiliated with NZDF, and does not expose operational military data.

Problem

Checking the situation around Wellington and the wider Indo-Pacific means bouncing between MetService, GeoNet, NZTA, news publishers, public webcams and geospatial portals. Their data arrives in different formats and update cycles. A list of headlines cannot show what is happening where; a map crowded with every dataset at once is just as hard to use. I wanted one geographic workspace that could switch between local and global context without implying that public reports were confirmed live operational information.

Constraints

  • Use only public, appropriately licensed information; no internal NZDF networks, live troop positions, readiness data or operational tasking.
  • Integrate inconsistent sources such as RSS/Atom, CAP warnings, JSON and GeoJSON APIs, ArcGIS services, radar imagery and media embeds.
  • Preserve accurate timestamps, source links and distinctions between live information, periodic snapshots, stale reports and historical records.
  • Keep national and global maps usable despite dense collections of markers, using layers, clustering and scale-dependent symbology.
  • Run as a browser application compatible with static GitHub Pages hosting; provider CORS restrictions and licence terms still apply.
  • Respect broadcaster restrictions: a playable channel or clip on an official site is not automatically embeddable in TREC.

Approach

I adapted World Monitor into a Trentham-oriented dashboard using a MapLibre geographic interface, NATO/APP-6-style symbols for publicly documented defence reference locations and separately styled civilian incidents. The layer manager offers local, New Zealand, Pacific and global contexts, with grouped markers that expand as the user zooms in. RainViewer supplies timestamped radar frames rendered as an automatically looping transparent overlay. Other panels bring in public weather conditions, GeoNet earthquake and volcanic information, road disruptions, NZ and international RSS news, radio and compatible public video feeds. I integrated selected public datasets from S2 Underground's Common Intelligence Picture through ArcGIS-backed services, retaining per-source attribution and freshness information. The application has been rebuilt and refined iteratively through production builds and browser tests; individual integrations remain subject to upstream availability.

Key Decisions

Make the map the organising interface, not just another panel

Reasoning:

The value comes from combining location, time and source provenance. A headline or earthquake report should link to its actual geography when that is supported by evidence, while national political stories should not acquire fictitious point locations just to appear on the map.

Alternatives considered:
  • Treat news, weather and incidents as unrelated scrolling panels
  • Geocode every mentioned place automatically, even when it is not the event location

Separate defence reference symbols from live incident reporting

Reasoning:

Publicly documented home garrisons are reference information, not live force tracking. Defence locations use military-style symbols only where appropriate, while weather, emergencies, road events and news retain distinct civilian event markers. The design avoids implying that static public reference data reveals deployments or readiness.

Alternatives considered:
  • Use identical NATO symbols for every event
  • Display all public facility markers as active operational positions

Animate genuine radar observations over the basemap

Reasoning:

The weather layer uses timestamped RainViewer frames with transparency and geographic alignment instead of a video widget or an artificially drifting static image. Rain and warning data remain separate: radar shows observed precipitation, while warnings come from the issuing authority.

Alternatives considered:
  • Embed a weather website in a player
  • Move a static rain image to imitate animation

Treat each data provider's freshness and permissions as part of the feature

Reasoning:

A successful request does not prove that its contents are real-time. Feed status, last updates, attribution, temporary outages and embeddability limits have to be visible; unsupported streams fall back to their official publishers rather than being presented as broken or silently rehosted.

Alternatives considered:
  • Mark every responding feed LIVE
  • Proxy or redistribute broadcaster media without permission

Prioritise information density without sacrificing legibility

Reasoning:

The same map must work at Trentham and world scale. Geographic clustering, category toggles, zoom-dependent labels, resizable panels and dedicated media views help control clutter. I found that showing everything simultaneously was less useful than showing fewer, better-explained signals.

Alternatives considered:
  • Render every icon and label at every zoom
  • Hide details permanently rather than make them accessible on demand

Tech Stack

  • TypeScript and React
  • Vite
  • MapLibre GL JS
  • GeoJSON and ArcGIS REST services
  • RainViewer radar imagery
  • RSS/Atom and public JSON APIs
  • GeoNet, Open-Meteo, MetService warnings and NZTA public data
  • Browser-based audio/video embeds
  • GitHub Pages-compatible static frontend

Result & Impact

The working prototype places New Zealand weather, geological events, public news and regional infrastructure context beside selected international datasets in one interface. Its map can shift from Trentham to global views while radar and public event layers remain independently controllable. News, public webcams, live TV, a continuously playing NZ news video channel, NZDF official social updates and radio have been integrated as separate, source-aware panels. The project is still ongoing: source availability, permissions, the volume of global event data and reliable geographic matching are active engineering challenges rather than solved problems.

Learnings

  • A large number of sources is only useful when the interface explains which information is current, approximate or historical.
  • Marker clustering, collision handling and symbol hierarchy have to be designed together; simply adding counts to existing icons makes congestion worse.
  • Browser restrictions, CORS, licensing and publisher embed policies are major system constraints, not implementation details.
  • Building a dashboard from public data requires careful distinction between facts, inferred relevance and official assessments.
  • Iterative browser testing at normal and ultrawide resolutions catches layout failures that a successful TypeScript build misses.

What it shows

The map centres on Trentham / Upper Hutt and switches between local, New Zealand, Pacific and global perspectives. Map layers include animated radar, geological hazards, public defence references, infrastructure, and selected CIP intelligence data. Public news, weather and media appear alongside their source and feed status. NZ Police releases and NZ news headlines are placed on the map at town level, labelled approximate.

Provenance and operational boundaries

TREC is an independent unofficial public-data demonstration, not affiliated with or endorsed by NZDF. Public home garrisons do not represent active unit positions or readiness. Individual feeds may be delayed, historical or unavailable, and broadcaster embeds remain subject to the publisher's terms.
