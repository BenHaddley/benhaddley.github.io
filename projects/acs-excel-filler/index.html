ACS Excel Template Filler

Creator · 2026 · 3 min read

A Flask web form that fills a real NZDF clothing issue/exchange Excel workbook — complete item lookup by material number or description, and a closeout mark drawn as real Excel line shapes instead of a pasted image.

Overview

A small local web tool for filling out the ACS clothing issue/exchange form: a browser-based form with an item picker backed by real NZDF material numbers, submitted to a Flask backend that writes the values directly into the official `.xlsx` template and hands back a completed workbook — not a re-typed lookalike.

Problem

Filling out the clothing issue/exchange spreadsheet by hand meant manually typing item descriptions and NZDF material numbers into the right cells, in the right row, without transposing a digit or misaligning a row — all while making sure any unused rows below the last item were still marked as void per the form's convention, rather than left blank and open to tampering.

Constraints

  • Output has to be the actual official `.xlsx` template, opened and re-saved with `openpyxl` — not a recreated lookalike, so existing formatting, merged cells, and print layout all had to survive untouched
  • Item entry has to resolve to one of a fixed set of real NZDF material numbers and descriptions (loaded from a static catalog), not free text, so the exported form is always valid
  • The form only has 10 rows to work with, so the UI and export logic both have to enforce that limit
  • Unused rows below the last real item still need a visible closeout mark, matching the paper form's convention of voiding out anything under the last entry so it can't be added to later

Approach

The frontend is a single HTML page with vanilla JS: a datalist-backed item picker matches whatever's typed against a bundled catalog of NZDF material numbers and descriptions, auto-filling both fields from either one. Submitting posts a JSON payload to a Flask `/export` endpoint, which loads the real template with `openpyxl`, writes the header fields and up to 10 item rows into their exact cells, and streams the filled workbook back as a download.

Key Decisions

Draw the closeout mark as real Excel line shapes instead of a pasted image

Reasoning:

An earlier version closed out unused rows with a static image overlay, which didn't scale or reflow with the sheet and looked visibly pasted-on when the workbook was printed or resized. Building the mark from real line shapes written directly into the drawing XML, anchored to actual cell/row coordinates, makes it a real vector element of the sheet that resizes and prints correctly like everything else on the form.

Alternatives considered:
  • Keep the original static image overlay
  • Leave unused rows blank

Manipulate the workbook's raw XML for the closeout lines instead of using openpyxl's drawing API

Reasoning:

openpyxl doesn't support inserting arbitrary shape drawings into a worksheet. Rather than drop the feature, the export step unzips the saved `.xlsx`, hand-builds the drawing XML part and its relationship files with `xml.etree.ElementTree`, and re-zips it — working underneath openpyxl only for the one piece it can't do.

Alternatives considered:
  • Drop the closeout-line feature entirely
  • Post-process the file with a separate Excel-manipulation library

Tech Stack

  • Python (Flask)
  • openpyxl
  • xml.etree.ElementTree (raw OOXML drawing injection)
  • Vanilla JavaScript
  • HTML/CSS

Result & Impact

Turns a manual, error-prone re-typing job into a guided form that only ever writes real, catalog-backed data into the official template — producing a completed workbook that's indistinguishable from one filled out natively in Excel, closeout marks included.

Learnings

  • Round-tripping a real `.xlsx` template through a library like openpyxl is usually enough, but the moment you need something the library doesn't expose — like inserting a drawing — you can drop down to editing the OOXML zip parts directly rather than abandoning the feature
  • Constraining input to a known catalog (material number ↔ description) up front is a cheap way to guarantee the exported document is always valid, instead of validating free text after the fact
