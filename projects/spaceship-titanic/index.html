How the project came together

Each step had an exit criterion. That kept model improvements attributable and stopped the leaderboard becoming the development set.

Phase 0 · Reproducibility first

Set up the project properly

I pinned Python 3.12 and every dependency with uv, authenticated the Kaggle CLI, and separated source code, notebooks, data, models, reports, and submissions. A fresh clone can recreate the same environment with one command.

uv sync → Kaggle CLI → train.csv / test.csv → versioned pipeline code
Phase 1 · Understand before optimising

Investigated the passenger data

Exploratory analysis established a balanced target, low and consistent missingness, no obvious train/test drift, and several pieces of structure hidden inside IDs, cabins, names, and spending.

The strongest discovery: 81.8% of CryoSleep passengers were transported, compared with 32.9% of passengers who were awake. None of the 3,037 CryoSleep passengers had non-zero amenity spending.

Groups always shared a HomePlanet, deck mattered, children behaved differently from adults, and surnames revealed family relationships that passenger groups alone did not capture.

Phase 2 · Establish a trustworthy floor

Built the simplest complete pipeline

The baseline median-imputed numerical fields, filled categorical gaps with the most frequent value, one-hot encoded categories, scaled numbers, and trained logistic regression. Five-fold stratified cross-validation produced 0.786 ± 0.010.

CSV → impute → encode / scale → logistic regression → five-fold CV
Phase 3 · Turn findings into features

Extracted the structure EDA revealed

Passenger IDs became group size and position. Cabins became deck, cabin number, and side. Names became surname-based family size. Five amenity columns became total spend and a no-spend flag.

I also encoded only evidence-backed imputation rules: positive spending can prove CryoSleep=False, while known groupmates can supply HomePlanet and sometimes deck. Keeping logistic regression fixed, these features raised CV accuracy to 0.792.

Phase 4 · Compare model families fairly

Moved from a linear model to boosting

Every candidate used the same engineered data and the same folds. XGBoost reached 0.795, LightGBM 0.809, and CatBoost 0.8155. A 40-trial Optuna search found no meaningful improvement over default CatBoost—useful evidence that more tuning was not automatically better.

Phase 5 · Test whether diversity helps

Combined models carefully

Equal-weight voting actually reduced accuracy because weaker models pulled CatBoost in the wrong direction. Weighting CatBoost and LightGBM 4:1 produced the best measured result: 0.8171 ± 0.006.

Ensembling was not free performance. The useful blend stayed close to the strongest model and gave the weaker model only enough influence to correct a small number of mistakes.
Phase 6 · Study what remained wrong

Generated leakage-safe out-of-fold errors

For every training passenger, the analysis stored a probability from a fold that had never trained on that passenger. CatBoost made 1,604 errors; the ensemble made 1,590. They disagreed on just 162 of 8,693 rows: the ensemble fixed 88 CatBoost errors and introduced 74 of its own.

The most difficult broad slices included eight-person groups, destination PSO J318.5-22, deck G, Earth passengers, and children. None exposed a clean, defensible correction, so I stopped rather than hand-fit rules to cross-validation noise.

Phase 7 · Ready for submission

Package the result, not just the model

The repository now trains reproducibly, saves fitted artifacts, predicts test.csv, and writes a correctly shaped PassengerId,Transported submission. The leaderboard has deliberately been held back until the final candidate is chosen.

What I learned

  • Good EDA produced more reliable gains than blind hyperparameter search.
  • Keeping folds and features fixed made every model comparison explainable.
  • A nominally better ensemble can still be effectively tied with a simpler model.
  • Error analysis is also a stopping tool: sometimes the honest next step is not another feature.

Current best: a 4:1 CatBoost/LightGBM soft-vote at 0.8171 ± 0.006 cross-validation accuracy. The full code, wiki, commands, and experiment history are available in the public repository.
