How the project came together

Each phase had an exit criterion. That kept improvements attributable and stopped the leaderboard becoming the development set.

Phase 0 · Reproducibility first

Set up the project properly

I pinned Python 3.12 and every dependency with uv, authenticated the Kaggle CLI, and separated source code, notebooks, data, models, reports, and submissions.

uv sync → Kaggle CLI → train.csv / test.csv → versioned pipeline code
Phase 1 · Understand before optimising

Investigated the passenger data

EDA established a balanced target, low missingness, no obvious train/test drift, and useful structure inside IDs, cabins, names, and spending.

The strongest discovery: 81.8% of CryoSleep passengers were transported, compared with 32.9% of passengers who were awake. None of the 3,037 CryoSleep passengers had non-zero amenity spending.

Groups always shared a HomePlanet, deck mattered, children behaved differently from adults, and surnames revealed family relationships.

Phase 2 · Establish a trustworthy floor

Built the simplest complete pipeline

The baseline imputed missing values, encoded categories, scaled numerical fields, and trained logistic regression. Five-fold cross-validation produced 0.786 ± 0.010.

CSV → impute → encode / scale → logistic regression → five-fold CV
Phase 3 · Turn findings into features

Extracted the structure EDA revealed

Passenger IDs became group size and position; cabins became deck, number, and side; names became family size; amenity columns became total spend and a no-spend flag. Evidence-backed imputation rules helped lift accuracy to 0.792.

Phase 4 · Compare model families fairly

Moved from a linear model to boosting

Using identical data and folds, XGBoost reached 0.795, LightGBM 0.809, and CatBoost 0.8155. A 40-trial Optuna search found no meaningful improvement over default CatBoost.

Phase 5 · Test whether diversity helps

Combined models carefully

Equal-weight voting reduced accuracy. Weighting CatBoost and LightGBM 4:1 produced the best measured result: 0.8171 ± 0.006.

Ensembling was not free performance. The useful blend stayed close to the strongest model and gave LightGBM only enough influence to correct a few mistakes.
Phase 6 · Study what remained wrong

Generated leakage-safe out-of-fold errors

CatBoost made 1,604 errors; the ensemble made 1,590. They disagreed on only 162 of 8,693 rows. No slice exposed a clean correction, so I stopped rather than hand-fit rules to cross-validation noise.

Phase 7 · Ready for submission

Package the result, not just the model

My results suggest that around 80–82% is the practical ceiling for this dataset. CatBoost and the ensemble agree on 98.1% of predictions, while tuning and ensembling produced almost no improvement. That suggests much of the remaining error comes from information missing from the passenger record rather than weak models.

The hardest cases are also where strong features such as CryoSleep, group structure, and deck provide the least certainty. A final leave-one-out group-outcome feature could test this; if it also fails to improve CV, I would consider the ceiling effectively reached.

The repository then packages the chosen pipeline, predicts test.csv, and writes a correctly shaped Kaggle submission.

What I learned

  • Good EDA produced more reliable gains than blind hyperparameter search
  • Keeping folds and features fixed made model comparisons explainable
  • A better ensemble can still be effectively tied with a simpler model
  • Error analysis is also a stopping tool
